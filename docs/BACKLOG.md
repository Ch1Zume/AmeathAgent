- 更新：2026-11-02；实施：本轮开发。
- 目标：每回合先估算伤害与来伤、一次规划整回合，能斩杀不额外防御；遇到新敌人先分析特点定打法；开局、精英/首领后、新一幕和牌组变化后回顾流派，并让后续选择服从它。

- 验收：真实游戏中一回合通常只调用一次模型；抽牌或目标死亡后能重算而不执行过期计划；至少一次精英战后的回顾，之后的选牌与回顾方向一致；开场分析与实际敌人机制相符。
- 证据：`tests/test_game_planning.py`；[2026-11-02 验证](validation/2026-11-02-game-planning-voice-usage.md)。尚无真实模型或游戏样本。
- 限制：伤害计算由模型完成，`combat_summary` 只做来伤与有效血量的辅助估算；桥接没有能力说明文字，模型对 STS2 敌人的了解可能不准；精英/首领依赖进入前的地图节点类型。

## AM-015 · 游戏算账、流派、路线与复盘

- 更新：2026-11-06；实施：本轮开发。来源：用户反馈“算伤害不计增益减益、战斗外废话多、没体现流派构建和路线规划、需要复盘”。
- 目标与落点：
  - 增减益：`game_analysis.combat_math` 读取我方/敌方能力（完整对象或紧凑字符串），按 `dynamic_values` 基础值或规则文本，计算每张手牌对每个敌人的伤害（力量、虚弱 ×0.75、目标易伤 ×1.5、无实体 =1、多段、群体）与格挡（敏捷、脆弱 ×0.75），在能量内枚举出对每个敌人的最大伤害与能否击杀，以及最大格挡、荆棘提醒；放入 `combat_summary.math`，提示词要求以此为准。
  - 少说话：非战斗 `step` 的台词和评论由代码清空；阶段回顾台词最多 1 句；界面只在战斗回合规划时显示“我在看看”；路线规划不出声。
  - 流派：回顾输出 `core_cards`；非战斗决策和回顾附 `deck_summary`；`step` 输出 `build_fit` 并写入记录；游戏页顶部常驻流派/核心/优先/路线。
  - 路线：`route_candidates` 从 `map.nodes` 全图枚举到顶部的路径，每个下一站选出有代表性的几条（精英多、最稳、休息+商店多、事件+宝箱多）；`route` 任务选一条后按坐标逐步前进（`routed`，不调用模型）；偏离、回顾、新一幕、血量 <40% 且下一站为精英时重规划。
  - 复盘：`run_log` 记录战斗（敌人、回合、血量变化、打法）、回顾、路线和非战斗选择；游戏结束（自主游玩中或读取局面时）调用 `postmortem`，结果写 `.local/game_reviews.jsonl`；最近 3 局的经验进入后续 `review`/`route` 的 `past_lessons`；「历次复盘」查看。
- 验收：真实游戏中算账数字与游戏显示一致（尤其易伤、虚弱、多段）；地图界面一幕通常只规划 1–3 次；选牌理由能对应流派；战斗外基本不出声；打完一局后复盘内容与实际经过相符，下一局回顾能引用经验。
- 证据：`tests/test_game_analysis.py`（12 项）及原有游戏测试；[2026-11-06 验证](validation/2026-11-06-game-schedule-packaging.md)。尚无真实模型或游戏样本。
- 限制：桥接文档未说明 `current_value` 和意图伤害是否已含增减益，本实现以基础值自行计算、意图采用游戏显示值，需实机核对；不计入本回合打出后才生效的增益、遗物和特殊卡效果；紧凑快照若不含 `map.nodes` 坐标则退回逐步选路线；复盘只在本会话从对局中途或开局一直接管时有完整记录。

- 行为：提醒时间到达后只提醒一次；重复日程提醒后移到下一次；应用关闭期间错过的单次提醒在开始后 2 小时内补发，重复日程启动时顺延；聊天添加的日程不能早于当前时间，最多 3 条。主动消息和屏幕观察不会添加日程。
- 验收：实际使用几天确认提醒时间与朗读、托盘通知；真实模型样本中，明确要求时能正确换算“明天/下周三/半小时后”，含糊时先问，普通聊计划不会误加。
- 证据：`tests/test_schedule.py`（8 项）。未调用真实模型，未在 Windows 桌面实测提醒。
- 限制：没有“稍后提醒”；提醒依赖应用在运行；时间为本机本地时间，不处理时区切换。

## AM-005 · 跨会话往事与角色日常

- 更新：2026-10-27；实施：本轮开发。用户决定先补功能、之后统一验收。
- 目标：重启或新对话后仍能按摘要提起真实聊过的事，角色原创日常可以跨会话延续；两者与用户事实记忆分开，可查看、删除、关闭。
- 落点：`memory.py`（同一 SQLite 中的 `episodes`、`pending_turns`）、`chat.py`（`EPISODE_SYSTEM`、`ChatAgent.consolidate`、聊天上下文注入）、`chat_ui.py`（记录与触发）、`companion_ui.py`「往事与日常」页、`Settings.session_memory`。
- 行为：仅模型模式且启用人设与记忆时记录真实回复；演示、主动问候、迟到回复不记录，含敏感词的轮次不记录。待整理轮次满 12 轮时后台整理最旧的部分（保留仍在上下文中的 6 轮），新对话和下次启动时整理全部；整理成功才删除原文，失败保留等待下次（上限 60 轮）。往事最多 120 条，日常按话题更新、最多 30 条。关闭开关会丢弃未整理的原文。
- 验收：存储、上限、敏感过滤、整理成功/失败/取消、上下文注入与开关、UI 列表删除清空和启动整理均有自动回归；还需真实模型样本，确认摘要只写真实发生的内容、日常延续自然、不过度翻旧账。
- 证据：`tests/test_episodes.py`（11 项）；[2026-10-27 验证](validation/2026-10-27-companion-features.md)，全量 `pytest` 235 通过 / 1 跳过 / 1 失败（失败项为改动前即存在的 `test_pet.py` 右键菜单用例，Linux offscreen、PySide6 环境）。尚未调用真实模型。
- 2026-11-01 缺陷修复（用户反馈：早上提到一段旋律后，一整天聊什么都绕回旋律，道别时仍说“还没想好”）：
  - 原因：最近 4 个日常话题每轮无条件注入；被提起后整理流程刷新更新时间使其一直排第一，且话题没有结束状态；交流约定和示例偏重旋律；闲时分享鼓励“接着讲进展”。
  - 改动：`episodes` 增加 `status`（open/closed）和 `last_mentioned`（旧库自动迁移）；聊天只注入与本条消息相关的日常（话题名重叠，或摘要重叠 ≥4 个二字词，最多 2 条），并附 `mentioned_today`；回复/主动消息在送达时按内容记录提起时间（轮次检查之后，迟到回复不写）；整理要求列出提到的已有话题并可标 closed；闲时分享只给一件最久未提、未结束且今天没提过的话题，送达后才记为已提起；去掉 `CHAT_DELIVERY` 中专讲旋律的规则，三条音乐示例改为游戏和点子纸片；主卡日常段增加“同一天不围着同一件小事打转”。往事日期与整理材料时间改用本地时区。
  - 证据：`pytest tests/test_episodes.py`（18 项，新增 7 项）；全量 `pytest` 261 通过 / 2 跳过 / 1 失败（失败项为改动前即存在的 `test_pet.py` 右键菜单用例，已在未改动代码上复现；Linux offscreen、PySide6、`.venv`）。未调用真实模型；需要实机挂一天确认是否还会固着。本机运行卡 `.local/persona.json` 需在 Windows 上备份后同步主卡。
- 限制：摘要质量依赖模型；整理进行中点击「全部清空」，正在生成的那一批仍可能在清空后写入；相关性仍是字面重叠，不是向量检索；用词完全不同的提起（如“那首歌”对“改曲子结尾”）可能注入不到或记不到“今天已聊过”。

## AM-008 · 可控的主动陪伴

- 更新：2026-10-27；实施：本轮开发。
- 目标：她能偶尔先开口，同时把“何时不说”做成程序规则，而不只写在提示词里。
- 落点：`companion.py`（`CompanionPolicy` 规则、`ProactiveCompanion` 控制器）、`ChatAgent.proactive`、桌宠右键「允许主动找我聊」「安静两小时」、`Settings.proactive_enabled/proactive_daily_limit`。
- 触发：久别问候（与应用互动间隔 ≥3 小时后再次互动，可顺着往事摘要问后续）；闲时分享（≥25 分钟没聊天且 90 分钟内有过互动，分享角色日常进展）。模型可以返回空回复，表示不说。
- 不说的条件：默认关闭；23:00–07:00；每日上限（默认 3）；任意两次间隔 ≥45 分钟；番茄钟进行中、天气问候待送、阅读/游戏任务中、聊天正在等待或输入框打开、桌宠睡觉或入退场时不发起闲时分享；右键或在聊天中明确说“安静一会儿/别打扰/少说两句”等，静默 2 小时。送达前再检查一次：用户已发消息、正在输入、已要求安静或已关闭时作废。主动消息不会触发飞行或睡眠，也不写长期记忆；演示模式不发起。
- 验收：安静识别正反例、规则组合、上限与冷却、空回复、迟到/打字作废、关闭开关、右键菜单均有自动回归；还需真实模型样本与实机长时间挂机体验，确认频率和内容不打扰。
- 证据：`tests/test_companion.py`（16 项）；[2026-10-27 验证](validation/2026-10-27-companion-features.md)。未调用真实模型。
- 限制：久别问候与闲时分享只依据本应用内的互动判断用户是否在场，不读取系统输入或屏幕（独立屏幕观察见 AM-011）；“安静”用关键词识别，只覆盖明确说法。

## AM-009 · 聊天流式输出

- 更新：2026-10-27；实施：本轮开发。
- 目标：不再等完整回复才开始播放；`reply` 数组里每闭合一个气泡就淡入一个。
- 落点：`ModelClient.stream`（Chat Completions SSE，逐块检查取消，忽略 `reasoning_content`，结束原因与非流式一致）、`partial_bubbles`、`ChatAgent.answer(on_partial=)`、`ReplyBubble.extend_sequence`（流式中播完已到气泡后等待）、`ChatDialog.on_partial`、设置「流式显示」（`Settings.stream_chat`，默认开）。
- 行为：最终结果与已播放部分一致时原地续播，否则（例如自动重试后）整轮重播；取消、新消息、出错后迟到的片段不显示，也不写入历史。Responses 接口和演示模式仍是一次性返回。动作、记忆仍在完整回复后处理。
- 验收：增量解析单调、对本地 SSE 服务的真实 HTTP 读取、截断和中途取消、首泡早于完成且不重播、取消后无迟到气泡均有自动回归；还需在 DeepSeek 实际服务上确认流式分块与首泡延迟。
- 证据：`tests/test_streaming.py`（7 项）；[2026-10-27 验证](validation/2026-10-27-companion-features.md)。未调用真实模型。
- 限制：只有模型按约定输出 `reply` 数组时才能逐泡显示；返回纯字符串或纯文本时退回到完成后显示。

## AM-010 · 语音朗读接口

- 更新：2026-10-27；实施：本轮开发；按用户要求只做接口，API 由用户自行接入。
- 目标：回复气泡可以被朗读，能被打断，失败时回到纯文字。
- 落点：`ameath/tts.py`——`SpeechProvider.synthesize(text, cancelled) -> SpeechAudio`、`register_provider`/`create_provider`、占位实现 `CustomSpeechProvider`（未接入时给出提示）、`speakable_text`（去掉 Markdown，代码、公式、表格不朗读）、`WinsoundBackend`（Windows 自带异步 WAV 播放）、`SpeechQueue`（按序合成、预取下一段、轮次作废、出错只提示一次）。`ChatDialog` 在流式气泡、完整回复和主动消息时朗读，新消息/取消/收起/新对话时停止，朗读中不自动收起。设置「语音」「音色」（`tts_enabled` 默认关、`tts_provider`、`tts_voice`）。
- 验收：顺序、流式不重复、禁用、新回复打断、失败回退、无播放器提示、聊天接线均有自动回归（假接口与假播放器）；接入真实 API 后还需在 Windows 上确认 `winsound` 播放、停止与时长估计。
- 证据：`tests/test_tts.py`（7 项）；[2026-10-27 验证](validation/2026-10-27-companion-features.md)。`WinsoundBackend` 在本次 Linux 环境中未运行。
- 更新：模型设置新增 MiniMax 同步接口、服务地址、模型、音色 ID 和独立密钥配置；默认使用国内地址，国际账户需切换至国际地址。密钥可选 Windows 加密保存或通过 `AMEATH_TTS_API_KEY` 提供。
- 本次验证：Windows 上使用 Qt offscreen 运行 `tests/test_tts.py tests/test_ui.py tests/test_transport.py tests/test_core.py`，40 项通过；包含本地模拟 HTTP、重定向限制、错误响应和独立密钥加密保存。未调用真实 MiniMax 服务或测试实际音频播放。
- 本地音色更新：安装 AemeathVoice/GPT-SoVITS 到 `.local/aemeath-voice/`，设置中可选择并按需启动，退出停止。实际生成样本并测量资源，长静音会重试；试听相似度和长时间使用仍待用户验收。详见 [本地语音验证](validation/2026-10-27-local-aemeath-voice.md)。
- 后续优化：保留参考音色但不向语义模型输入参考台词；识别语音片段及静音异常，失败限次重试。气泡拆为短句，第一句可在后续句子生成时播放。相关自动回归 81 项通过；真实模型和延迟样本见 [逐句与质量验证](validation/2026-10-27-voice-streaming-quality.md)。离线识别并非人工验收，仍可能误判；真实桌面连续聊天和人工音色试听待验收。
- 后续调整：开启朗读时，按句在语音开始播放时显示文字，合成失败自动回退显示文字；关闭朗读仍沿用原有淡入。保留自然的“嗯”等语气词，升级离线识别以降低误判。项目根目录只保留 `启动AmeathAgent.cmd`，游戏仍可通过桌宠右键或主界面进入。验证见 [同步实测](validation/2026-10-27-voice-text-sync.md)。
- 下一步：用实际 MiniMax 账号、音色和 Windows 播放进行验收；自定义 provider 仍可通过注册机制扩展。
- 2026-11-02 提速（用户要求）：首句在逗号处截短到约 16 字；两路预取并行合成、按序播放；40 字以内短句缓存复用；启动 4 秒后及修改设置后预热本地模型；服务端 GPU 合成与 CPU 识别分锁，下一句合成可与上一句校验重叠。识别参数与阈值不变。仅自动回归，待在 Windows + GPU 上测首句时间与句间停顿，见 [验证记录](validation/2026-11-02-game-planning-voice-usage.md)。
- 限制：默认播放器只支持 WAV；动作与语音尚未逐句同步；没有语音输入（STT）。

## AM-011 · 定时屏幕观察与主动交流

- 更新：2026-10-27；目标：根据用户明确开启后的屏幕画面，偶尔自然主动交流。
- 落点：`screen_observation.py`、`companion.py`、模型设置、桌宠右键；独立的视觉服务与密钥。
- 行为：默认关闭；每 5–180 分钟检查，默认 15 分钟，鼠标所在屏幕整屏截图发给兼容 Chat Completions 的视觉模型。共享主动陪伴的 45 分钟冷却、每日上限和安静时段，忙碌时跳过；屏幕观察可唤醒睡觉的桌宠。关闭、用户消息和设置变化使待处理回复失效。
- 验收：独立密钥、关闭、定时、忙碌、静默、取消、输出动作和截图载荷有自动回归；待真实视觉服务验证论文、视频、聊天、纠正与安静的多轮效果，以及 Windows 多屏、锁屏与可见性人工检查。
- 验证与限制：见 [定时屏幕观察验证](validation/2026-10-27-screen-observation.md)。截图发送后不可撤回，服务可能保留或收费；没有系统级在场判断，模型可能理解或表达错误。
