# 2026-10-27 本地爱弥斯语音质量与逐句播放验证

## 改动

- 上游推理将参考音频的语义和文字加入 GPT 提示，测试时出现参考台词混入。`ameath/local_voice_inference.py` 基于上游 MIT 实现，保留参考音频的声学特征，但仅将目标文字送入语义模型；参考音色仍被使用。
- 拒绝未正常结束的语义解码及连续长静音；使用 `.local/aemeath-voice/asr-check` 的 CPU Whisper base 离线识别，按中文拼音比较输入与语音，并检测参考台词和明显的额外前后缀；每句最多生成三次。模型未通过检查时停止朗读并保留文字。检查是启发式的，可能误判或漏判，尤其是短语、英文和数字；不保证绝无漏读或失真。
- 本地语音将每个完整气泡拆成有序短句，单句最长 45 字，优先在标点处分割。队列按句预取：第一句就绪后开始播放，同时生成下一句。连续流式气泡按前缀去重，取消后的迟到响应不播放。
- 语音服务由 `.local/aemeath-voice/venv` 启动；Whisper 模型和识别在本机执行，不保存识别出的聊天文本。`faster-whisper` 延后加载，以避免 Windows GPU DLL 初始化冲突。

## 运行与结果

- 本机 Windows、RTX 4070 Laptop 8 GB；同时有桌宠语音服务使用 GPU，非独占基准。
- Qt offscreen：`python -m pytest tests/test_tts.py tests/test_speech.py tests/test_streaming.py tests/test_chat.py tests/test_ui.py -q -p no:cacheprovider`：81 passed。包含第一句播放时第二句仍在合成、流式续接去重、切换释放、长静音与漏读/参考台词检查。
- 参考语义去除实验：3 条不同的中文短句，各合成两次，六段均产生非静音音频，离线识别结果覆盖主要句意；测试样本不代表稳定性或人工听感。
- 真实桌宠队列：同一条 82 字、3 句的长回复运行两次，使用记录播放调用与音频时长的模拟播放器。冷启动首句开始播放 21.29 秒；同一服务保持加载后的第二轮首句 4.11 秒、第二句 9.66 秒、第三句 17.64 秒。第二轮音频时长依次为 5.40、7.80、6.04 秒。先前整气泡生成测试同样文本耗时 16.93、19.10 秒才可开始播放；不同运行负载和随机性使其仅为参考。
- 最终六个长回复片段的离线识别覆盖主要句意，未识别到先前的参考台词；仍存在识别近音字，无法仅凭语音识别断言发音准确。合成样本位于 `.local/preview/aemeath-voice/improved/`；尚未进行人工听感、真实 Windows 声音设备和长时间连续对话验收。
- 同一条此前出现长静音的 120 字回复，最终检查阈值下分成 5 句，冷启动首句开始播放 19.67 秒，后续句子 26.99、34.90、40.61、45.78 秒开始，使用模拟播放器。中间第一、二句之间约有 3.6 秒额外等待；质量重试可能造成句间停顿。五句均返回音频且通过离线检查，识别覆盖主要句意，但第一句仍可能遗漏一个“了”；识别也有近音字误差，未做人工试听，不能保证没有漏字。
- 最终严格阈值下再次测试 82 字、3 句回复：冷启动首句 19.49 秒，模型保持加载的下一轮首句 3.97 秒，第二、三句分别在 8.80、14.50 秒进入模拟播放；单次样本并非延迟保证。
- 部署运行中的桌宠需要重启以加载新代码；不影响保留的 MiniMax 接口和密钥。
