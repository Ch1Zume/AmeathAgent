# 2026-11-02 游戏回合规划、游戏语音与全局用量验证

## 背景

用户在 Windows 实机完成了 STS2 桥接游玩测试，反馈运行顺畅（AM-004），并提出：回合开始先全局规划；全局记录 Token 并按日/周/月与用途统计；游戏台词接入语音和人设；语音提速；阶段性构筑回顾；遇敌时的战术思考。

## 改动摘要

- `ameath/game.py`：战斗中每回合一次 `turn_plan` 调用，给出伤害估算（`math`）、是否斩杀（`lethal`）和按卡名/目标描述的整回合步骤；之后每步与当前合法动作按名称与目标匹配，不调用模型。抽到或生成新牌、计划的下一步不可用、计划用完但回合未结束时 `replan`，每回合最多 3 次，之后退回单步决策。第一步不合法时改用一次单步决策，不猜测。每场战斗第一回合（`opening`）同时生成本场打法 `combat_strategy`，后续回合沿用。
- 阶段回顾 `review`：开局（或中途接手）、精英/首领战后、进入新一幕、牌组新增 ≥4 张时，在下一个地图界面进行；结果作为 `strategy` 传入之后所有决策。
- 所有游戏调用共用一个静态系统提示：游戏规则 + 用户人设卡 + 说话规则，以便服务方复用前缀缓存。台词 `speech` 最多 3 句，每句不超过 60 字；情绪不包含飞行/睡眠。
- `ameath/game_ui.py`、`ameath/chat_ui.py`、`ameath/app.py`：台词经聊天回复气泡与朗读队列播放，播放完才执行下一步（超时 60 秒）；聊天正在进行时不抢话，退回桌宠文字气泡并留出阅读时间。游戏台词不写入聊天历史。暂停时停止游戏台词。
- `ameath/usage.py`、`ameath/usage_ui.py`、`ameath/llm.py`：共用模型客户端记录每次收到的响应用量（含空答等无法使用的响应），保存到本地 `usage.db`：时间、用途、细项、模型名与 Token 数，不保存提问或回复。主界面新增「用量记录」，按日/周/月显示总量、各用途占比、趋势和细项。
- `ameath/tts.py`、`ameath/local_voice_server.py`：每次回复的第一句在逗号处截短（≤16 字）以便更早出声；两个预取线程并行合成，播放顺序不变；40 字以内的重复短句复用音频；启动 4 秒后与修改设置后在后台预热本地语音模型；服务端 GPU 合成与 CPU 识别校验改为分开加锁，下一句可在上一句校验时合成。校验阈值和识别参数未改。

## 运行与结果

- 基线（改动前）：`QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -p no:cacheprovider`，261 通过、2 跳过、1 失败（`tests/test_pet.py::test_right_click_commands_expose_sitting_sleeping_waking_and_flight`）。
- 改动后同一命令（Linux 开发机，Qt offscreen）：278 通过、2 跳过、1 失败，失败项与基线相同，与本次改动无关，未修复。
- 新增回归：`tests/test_game_planning.py`（10 项：单次规划驱动整回合且索引随手牌移动、新抽牌触发重算、重算上限后退回单步、不合法首步不猜测、开局与精英后回顾并传入后续决策、步骤精确匹配、台词限制、来伤估算、面板等语音播完再执行、聊天占用时退回文字）；`tests/test_usage.py`（4 项：用量字段兼容、日/周/月归并与未知计数、真实本地 HTTP 往返按用途记录且不含提问文本、用量页三种周期渲染）；`tests/test_tts.py` 新增 3 项（首句截短不丢字、双线程预取保持播放顺序与短句复用、游戏台词不进入聊天历史且不打断聊天）。`tests/test_deepseek.py` 的游戏假客户端改为接受新的 `detail` 参数并返回回合计划，断言不变。
- 主窗口离屏冒烟：新导航页显示 `UsagePanel`，游戏台词路由在关闭朗读时返回 `text`；用量页用合成数据截图检查了日/周布局。

## 未验证

- 没有调用真实 DeepSeek 或真实游戏验证回合规划的质量、斩杀判断准确度、实际节省的调用次数、台词是否贴合人设，以及战斗开场对具体敌人（如养蜂人）的分析是否正确。模型对 STS2 敌人机制的了解有限；桥接状态中的能力没有文字说明。
- 精英/首领判断依赖进入战斗前所选地图节点的类型；中途接手时若不知道节点类型，只在奖励含遗物时补做回顾。
- 语音提速只有自动回归，没有在 Windows + GPU 上测量首句时间或句间停顿；并行合成对 MiniMax 的限流影响未测。
- 用量记录只统计服务方报告的 Token，不是账单金额；网络失败未收到响应的请求不记录。
