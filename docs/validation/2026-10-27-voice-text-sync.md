# 2026-10-27 语音与文字同步验证

## 改动

- 开启语音时，聊天气泡在合成期间提示“正在准备语音”，每句在对应音频调用播放器时立即显示；其余句子预取。用户可通过“显示全部”提前查看已生成文字，合成或播放失败时自动回退显示，流式续接不重播，取消后的旧响应不显示。关闭语音时保留原淡入表现。
- 支持单句和多个气泡的同步；包含代码、链接或 Markdown 强调的气泡作为整体处理，避免破坏标记。主动陪伴同样走同步路径。
- 本地语音质量检查容许额外自然的“嗯”等短语气词，但不主动添加或改写音频；仍拦截参考台词和明显漏读。离线校验优先使用 `.local/aemeath-voice/asr-check-small/`，缺失时退回原 base 模型。small 来自 [Systran/faster-whisper-small](https://huggingface.co/Systran/faster-whisper-small)，模型页列明 MIT；483,546,902 字节的模型文件按 Hugging Face LFS SHA-256 校验，模型和音频均在本机使用，不记录识别内容。
- 项目根目录保留 `启动AmeathAgent.cmd`，另两个原入口移至 `.local/backups/launcher-20261027/` 并改为 `.txt`；游戏仍可从桌宠右键或主界面进入。

## 验证

- Windows，Qt offscreen：`python -m pytest tests/test_tts.py tests/test_speech.py tests/test_streaming.py tests/test_chat.py tests/test_ui.py -q -p no:cacheprovider`，87 passed。覆盖语音前文字不提前出现、逐句播放与显示、流式完成、失败回退、取消、Markdown 和自然“嗯”。
- 本机合成测试消息，使用真实已配置的聊天模型和本地语音，通过离屏 `ChatDialog` 和模拟播放器记录调用时间；未把测试聊天写入长期记忆。一次 base 识别器测试中第一句连续三次校验失败，约 35.25 秒后回退到文字。small 识别器的另一次测试中，第一段文字在 8.56 秒收到但未显示，第一句音频调用在 42.255 秒，文字在 42.256 秒显示；第二句分别为 50.368 和 50.369 秒。语音服务冷启动且有一次候选重试，时延包含真实模型响应及本机语音处理，不能当成热启动基准。
- 对先前测试片段，小模型把 base 误识别的“一句一句”识别正确；一段短样本的 CPU 离线识别耗时 base 约 0.52 秒、small 约 1.66 秒，分别加载约 0.36 和 1.05 秒。一次样本不能代表一般延迟，small 仍可能误判导致等待或停止朗读。没有对音色或设备做人工听感判断；离屏模拟播放器不代表真实桌面或扬声器验收。
