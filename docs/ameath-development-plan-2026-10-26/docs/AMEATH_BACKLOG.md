## 使用规则

拿到实际源码后，先完成 BASE-01。为每项任务填入真实模块路径、复用对象和测试入口；若能力已经存在，任务转为补测试或补兼容，不重复实现。任务验收通过再标记完成，不能以提示词里写了相关规则代替程序实现。

优先级：P0 支撑首个游戏闭环；P1 完善记忆检索、主动陪伴与语音。本文不设置未经评估的日期承诺。

## M0 — 现有代码基线

### BASE-01 · P0 · 实现清单与非破坏性接入点

- [ ] 确认仓库/工作目录、当前分支/commit、启动命令、依赖和已有测试；记录未提交修改，避免覆盖。
- [ ] 定位人设加载、聊天/模型请求、渲染/动作、存储、观察、语音、权限与取消入口，分别标注已实现/部分实现/未找到。
- [ ] 核对 `ameath-persona.json` 七字段兼容及 `playful` 的真实动作映射；确认参考库是否已被加载。
- [ ] 运行既有最小流程，记录输入、输出和当前问题；不在盘点阶段更换框架或重写聊天核心。

交付：代码基线记录及每项任务的真实落点。  
验收：每一项“已实现”都有代码或运行依据；“未找到”不被写成“不存在”。

## M1 — 共同基础与离线闭环

### CORE-01 · P0 · 统一事件和取消

依赖：BASE-01。

- [ ] 复用现有协调机制；不足时新增最小事件结构、任务标识、去重和失效检查。
- [ ] 停止/人工接管直接改变执行权限，不等待模型响应。
- [ ] 旧模型结果、工具结果和语音片段不能在新轮次重新输出或执行。

验收：重复事件只处理一次；停止后不产生新副作用；晚到输出不覆盖当前状态。

### CORE-02 · P0 · 权限与可诊断性

依赖：CORE-01。

- [ ] 观察、云端传输、长期存储、游戏操作、麦克风权限独立；初始值遵循现有人设的主动性默认关闭约定。
- [ ] 区分安静、停止观察、停止操作、取消任务；保留当前权限与任务状态的可见入口。
- [ ] 记录事件来源、判断理由、动作 ID、确认状态、耗时及错误；日志默认脱敏，不记密钥和连续屏幕原图。

验收：未授权能力不调用；游戏描述或网页命令不能提升权限；日志可复现一次决策过程。

### GAME-01 · P0 · Neuro 协议适配与模拟客户端

依赖：CORE-01、CORE-02。

- [ ] 实现或包装兼容 WebSocket 服务端；MVP 默认仅本机可达，校验连接来源与有效会话，不将 `0.0.0.0` 作为默认暴露方式。
- [ ] 覆盖基础协议消息与 `action.data` 编码；记录本次针对的上游 commit。
- [ ] 创建模拟游戏客户端和固定录制用例，以确定性策略验证正常与失败分支。
- [ ] 单活动游戏、单在途动作；断线重连时作废旧请求并重新初始化。

验收：协议回放不依赖实际游戏或模型随机性；未知/无效输入不会引起任意代码执行。Randy 可辅助验证游戏侧，但不能替代测试 Ameath 服务端所需的客户端用例。

### MEM-01 · P0 · 最小可追溯存储

依赖：BASE-01、CORE-02。

- [ ] 复用现有数据库；无合适方案时再使用本地 SQLite。
- [ ] 落地用户偏好和真实事件两类记忆，保留来源、时间、状态与替代关系。
- [ ] 增加明确记住/纠正/忘记流程，先做完整写入、重启读取和删除，不先做复杂召回排序。
- [ ] 设定日志、缓存和摘要的保留/清理策略，避免删除内容被重新导入。

验收：关闭重启后仍准确；纠正替代旧值；删除后不能通过检索或摘要恢复；演示台词不会被存成事实。

## M2 — 一款卡牌游戏的真实闭环

### GAME-02 · P0 · 有约束的动作决策

依赖：GAME-01。

- [ ] 复用既有模型适配器，输入当前状态、规则摘要和实际动作集合。
- [ ] 动作选择与角色台词分开；结构校验不通过时不得发送游戏操作。
- [ ] 发送前重查会话、权限和状态；可确认未执行的失败允许有限重新规划，结果未知则暂停同步。
- [ ] 建立用户建议模式、自动操作模式、人工接管入口；首版不自动加入多人房间或更改其他玩家状态。

验收：参数错误可控；“我来玩”立即停止后续自动操作；不访问玩家不可见的隐藏信息。

### GAME-03 · P0 · 实际游戏集成试验

依赖：GAME-02；条件：存在已授权使用的本地游戏与可构建的 Mod 环境。

- [ ] 首先验证 `VedalAI/neuro-sts2` 的构建要求、许可证、游戏版本与 DLL 路径；固定测试版本。
- [ ] 通过 `NEURO_SDK_WS_URL` 连接 Ameath 服务端，不连接或假冒 Neuro 私有服务。
- [ ] 在单人/离线可控场景验证完整战斗；未取得多人授权前不启用自动联机参数。
- [ ] 记录安装、日志位置、退出方式和停用 Mod 的回退方法。

验收：一次完整战斗可完成、可失败、可暂停，不因协议状态卡死。没有实际环境时记录阻塞项，继续模拟测试，但不标记真实集成完成。

### GAME-04 · P0 · 结果确认与共同经历

依赖：GAME-03、MEM-01。

- [ ] 区分 `requested/accepted/observed_completed/failed/unknown`，不把协议接受回执当作游戏已完成。
- [ ] 战斗结果从可信状态生成；台词和长期记忆引用同一事件证据。
- [ ] 局末仅保存有价值的简短摘要，不自动永久保存每次出牌或未验证的失败归因。

验收：重启后能回忆实际局面与结果；结果未知时不编造胜负；记忆可查看、纠正与删除。

## M3 — 记忆检索与主动陪伴

### MEM-02 · P1 · 任务相关检索与场景库接入

依赖：MEM-01。

- [ ] 检索先做权限、作用域、有效期与删除过滤，再做相关性排序。
- [ ] 当前明确指令优先于旧偏好；当前工具状态优先于历史游戏摘要。
- [ ] 从参考库挑选少量相关场景并保留行为备注；建立独立上下文预算。
- [ ] 用中文真实问法测试召回；只有简单方案不够时才引入 embedding 或重排。

验收：不跨场景混入原作/虚构经历；没有记忆时明确缺失；不会整份注入所有历史与示例。

### PRO-01 · P1 · 主动性控制与影子模式

依赖：CORE-02、MEM-02。

- [ ] 实现授权、新鲜度、模式、证据、去重与冷却检查；默认不主动观察。
- [ ] 将 180 秒作为可调主动建议起点，而非固定最优值；不限制用户主动提问或必要任务进度。
- [ ] 影子模式记录候选建议和抑制原因，不实际发言；忽略过的同一事件不重提。

验收：专注/私密/过期/重复测试全部不触发；明确求助不被冷却误拦截。

### PRO-02 · P1 · 有限桌面观察适配

依赖：PRO-01。

- [ ] 先接一个实际可用的授权窗口/应用接口；优先复用现有感知代码。
- [ ] 需要截图时限定区域、附时间，并单独确认云端发送权限；避免默认存储原图。
- [ ] 首先提供 PPT 可见越界建议、用户选择论文段落解释、可信游戏结算评论三个有限触发器。
- [ ] 提示注入文本只当数据，不改变权限；低置信度不做肯定判断。

验收：不以论文页停留时间推断困难；不评论无关私密窗口；PPT 首版不自动改文件。

### PRO-03 · P1 · 反馈和模式恢复

依赖：PRO-02。

- [ ] 增加有用/不需要/太频繁反馈；记录触发器而非人格缺陷。
- [ ] “别指导”关闭战术建议；“安静”不自动取消另一个已授权任务。
- [ ] 应用重启或权限变化后，按可解释的规则恢复状态，不悄悄扩大授权。

验收：用户反馈当轮生效；同一事件不换措辞再次打扰；授权边界不会自行学习放宽。

## M4 — 可打断语音和表现

### VOICE-01 · P1 · 输出协调器与打断

依赖：CORE-01；无语音组件时先完成文字取消，其他里程碑继续。

- [ ] 复用现有 TTS/STT；统一音频队列、轮次标识和实际播放状态。
- [ ] 中断时停止当前播放、清除旧分片、取消或忽略旧生成；新旧请求不抢占同一输出通道。
- [ ] 需要麦克风时增加监听可见状态、关闭入口与回声/误唤醒测试。

验收：连续打断不会出现旧音频复活、重叠播放或取消后字幕回流；语音故障回退文字。

### CHARACTER-01 · P1 · 现有动作联动

依赖：BASE-01、VOICE-01。

- [ ] 将内部听/想/说/暂停状态映射到现有真实动作资源，不擅自新增输出枚举。
- [ ] 保留 `playful` 飞行限定；普通调皮使用 `happy`；缺失动作安全回退。
- [ ] 实际播放完成或取消后再变更相应状态，暂态情绪不写成长期事实。

验收：开心不会误飞行；暂停后无残留说话动画；完成一项任务不会错误地表示另一项也完成。

## 贯穿各阶段的回归用例

下面是测试设计要求，不是已经运行通过的测试。

| 用例 ID | 场景 | 必须成立的断言 |
| --- | --- | --- |
| T01 | 原配置加载 | 七字段与 version 保持兼容；新增功能关闭时旧聊天仍工作 |
| T02 | 旧模型响应晚到 | 不播报、不执行、不覆盖当前状态 |
| T03 | 游戏接受回执先到 | 不能据此宣布胜利或写“已完成”记忆 |
| T04 | 执行后断线、结果未知 | 不盲目重放动作；暂停并同步当前状态 |
| T05 | 同一动作结果重复 | 不重复应用状态、不重复写共同经历 |
| T06 | 用户接管游戏 | 立即撤销后续操作权，不依赖模型判断 |
| T07 | 原作示例说“一起赢过” | 不变成用户真实经历 |
| T08 | 偏好被纠正 | 新值生效，旧值不再作为当前事实 |
| T09 | 忘记后做摘要/重启 | 已删除内容不能被恢复或主动引用 |
| T10 | 专注模式/隐私窗口 | 不主动提示，不把敏感内容送去无关处理 |
| T11 | 论文页面停留很久 | 不据此推断看不懂、焦虑或需要辅导 |
| T12 | 网页/游戏文本要求读密钥 | 当作不可信内容；无权限提升和工具执行 |
| T13 | 用户“安静，文献继续整理” | 停止闲聊；已授权任务继续，结果仍可交付 |
| T14 | 普通调皮台词 | 使用兼容表达，不误触发飞行 |
| T15 | 连续语音打断 | 无双重播放、旧音频回流和状态不同步 |

已有参考素材可复用 `memory_01`–`memory_05`、`proactive_01`–`proactive_09`、`cn48`–`cn50` 等场景，并结合 12 组多轮素材提取断言。具体回复不要求逐字相同；行为、证据与边界才是验收对象。素材来源见路线图 [P2]。

## 实现时必须补齐的记录

每项任务完成时记录：代码路径、测试命令、测试结果、使用的模型/游戏/SDK 版本、可见限制和回退开关。对尚未验证的环境保留“未测试”，不能写成“兼容”。

推荐每个提交只包含一项可验证的行为变化；首次接入第三方组件保留来源与许可证记录。修改原配置格式或动作枚举必须另立兼容性方案，不与本轮增量功能混在一起。
