# Ameath 的《杀戮尖塔 2》技能

## 设计

DeepSeek 是 Ameath 的统一模型核心。游戏技能读取游戏局面、构造此刻合法的动作选项，由同一模型核心选择动作，桥接模组负责把动作交给游戏。桌宠的评论来自模型的简短最终回答。

模组不配置模型、不接收 Ameath 的密钥；其内置 Auto-Play 应保持暂停，避免两个控制器同时操作。本轮选用 [STS2 AI Agent v0.16.2](https://github.com/CharTyr/STS2-Agent/releases/tag/v0.16.2) 的本机 HTTP 接口，接口依据为其 [版本对应的 API 文档](https://github.com/CharTyr/STS2-Agent/blob/v0.16.2/docs/api.md)。

## 当前安装

已识别本机游戏：

```text
E:\SteamLibrary\steamapps\common\Slay the Spire 2
游戏版本 v0.111.0
```

三个桥接文件已放入该游戏的 `mods` 文件夹。下载资产通过 GitHub Release 提供的 SHA256 校验；来源、版本与逐文件哈希见 `integrations/sts2/bridge-release.json`。第三方模组采用 AGPL-3.0，其许可证保留在 `integrations/sts2/UPSTREAM-LICENSE.txt`；Ameath 通过本机 HTTP 与它通信，没有把第三方模组代码合并进自己的模型核心。

首次启动需要你在 Steam 选择 **Play with Mods / 启用模组启动**，按游戏提示确认，启用 **STS2 AI Agent** 并重启。按 F8 打开模组面板，找到实际 HTTP 端口。常见为 `127.0.0.1:8080`，端口被占用时会变化。

如果已订阅同一模组的 Steam 工坊版本，保留一个安装来源，避免重复加载。安装脚本在发现工坊副本或不同版本的同名文件时会停止。

## 使用步骤

1. 在 Ameath 的「模型设置」里使用 DeepSeek 预设、填写密钥，保存。游戏和阅读共用这些设置。
2. 启动带模组的游戏，开始一局**单人**游戏；保持模组自身的 Auto-Play 暂停。
3. 在 Ameath 左侧点击「杀戮尖塔 2」，把来源从「演示局面」切换为「连接真实游戏」。
4. 填入 F8 面板显示的本机地址，点击「读取局面」。这个步骤不调用模型。
5. 可以先「只给建议」，再「执行这条建议」；也可以「决策并执行一步」或「开始自主游玩」。
6. 按 **Ctrl+Alt+P**、点击「暂停」，或使用桌宠右键的「暂停游玩」交还操作。

没有 API 密钥时，可以留在演示局面体验建议、执行与自动循环。这是固定的合成场景，不代表真实游戏表现。

## 支持范围

已映射战斗出牌、目标选择、药水、结束回合、地图、事件、休息点、卡牌奖励、宝箱、商店与常见选牌/卡包。

模型只能选本轮提供的动作 ID，不能生成任意鼠标坐标、控制台命令或其他系统操作。执行前会重新读取局面并核对动作。新抽牌、伤害或选项变化后重新决策；不会将旧的一串出牌计划直接执行到底。

游玩限于当前单人局。回到主菜单、换局、切换存档、游戏结束或打开人工暂停菜单时停止。多人、存档管理、放弃本局与调试命令不开放给这一版技能。水晶球小游戏、未知弹窗等尚未映射的特殊界面会等待并暂停，交给用户处理。

已提交的动作可能在按暂停后完成；暂停会阻止后续动作。超时后无法确认执行结果时会停止，不自动重复出牌。

## DeepSeek 适配

- 默认 `https://api.deepseek.com`、`deepseek-flash`、Chat Completions。依据 [2026-10-25 查询的官方接口文档](https://api-docs.deepseek.com/)。
- 普通解释默认关闭思考；游戏默认开启 `thinking` 并使用 `reasoning_effort: high`。依据 [思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。
- 游戏设置 `response_format: {"type":"json_object"}`，提示词明确 JSON 格式，输出额度为 8192 token。依据 [JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/)。
- 每一步是一个最终 JSON 决策，不携带 `tools`，不把 `reasoning_content` 拼进历史。若未来改为多轮工具调用，需要按官方要求回传完整工具回合消息。
- 历史只保留最近五步及有限长度的游玩目标，静态策略提示保持一致。没有测量真实速度、成本或胜率，因此这些是接口与上下文设计，不是性能提升保证。

## 用量与记录

默认单次游玩会话上限为 200 次请求、1,000,000 个服务方报告的 token。发起下一次调用前检查额度；在途请求可能让 token 数超过上限。没有用量信息时显示「未知」，不视为零。请求上限仍然有效。这不是金额封顶机制。

可以在开始前调整额度；要重置同一局的统计，点击「新游玩会话」。暂停后再次开始会延续现有计数。

`.local/game_sessions/` 中保存每步的提议/执行状态、动作、简短理由与评论、局面指纹及服务方用量。没有模型内部思考、密钥或原始截图。

## 已验证与待验证

开发检查覆盖 DeepSeek 参数、共用模型核心、目标索引、不可打卡牌、未知动作、暂停、旧局面、新对局、执行结果不明时的重复保护、用量与本地 HTTP 契约，并检查了界面与演示循环。

实际游戏启动检查发现游戏能识别已安装模组，但首次加载仍受游戏自身的模组启用确认阻挡；真实游戏桥接连通、真实 DeepSeek 决策、完整一局与游玩质量留待用户启用模组和配置密钥后验证。当前不把演示循环当作实机自主游玩的证据。

只读连通检查：

```powershell
.\.venv\Scripts\python.exe tools\probe_sts2.py --endpoint http://127.0.0.1:8080
```

重新准备或安装桥接时，先运行 `tools/prepare_sts2_bridge.py`，再运行 `tools/install_sts2_bridge.ps1 -ValidateOnly`；实际安装需要对游戏目录的写入权限。`tools/smoke_sts2_bridge.ps1` 是开发向的隔离档只读启动检查，默认使用新 clientId，拒绝覆盖已有设置；它不绕过首次模组确认。
