# AmeathAgent

Windows 桌面伙伴，v0.6.1 原型。**DeepSeek API 是 Ameath 的统一模型核心**；日常聊天、论文阅读、手动截图解释和《杀戮尖塔 2》游玩共用模型设置；定时屏幕观察使用独立视觉模型。

## 启动

项目文件夹为 `AmeathAgent`。双击 **启动AmeathAgent.cmd**。首次启动会在项目的 `.venv` 中安装依赖，需要 Python 3.11 或以上和网络。已配置好的开发环境可直接运行：

需要从正常 Windows 桌面会话启动交互界面；开发沙箱中的进程可能无法建立微软拼音的输入法上下文，表现为“已禁用输入法”。开发时可在沙箱里运行离屏测试，但交付给用户使用的窗口应通过正常桌面启动器启动。聊天和论文输入支持中文组字，确认候选时的 Enter 不会发送，完成选字后再次 Enter 才发送；Shift + Enter 换行。

```powershell
.\.venv\Scripts\python.exe main.py
```

启动时右下角会先播放声痕聚拢、像素小人现身的入场动画。**单击桌宠打开输入气泡，回复显示在她头上的另一个气泡里**，拖动时气泡会跟随。**右键 →「打开 Ameath」** 进入完整 App 页面，首次进入会载入原创教学示例。右键也可打开「记忆与人设」「天气与问候」「番茄钟」、动作、游戏和解释入口。鼠标离开桌宠、输入与回复气泡约 8 秒后会自动收起，保留草稿和本次对话；悬停、输入中文、等待回复或操作菜单时会延后收起。收起气泡会保留本次对话；关闭 App 页面会收起到桌宠和托盘，右键选择「退出 Ameath」会播放像素消散的退场动画后退出。

进入游戏技能面板可使用桌宠右键「玩杀戮尖塔 2」或主界面侧栏「杀戮尖塔 2」；它不会自动接管游戏。命令行也可使用 `main.py --game`。

## 现在可以做什么

- **气泡聊天**：未开启语音时，回复按完整意思分成多个小气泡依次淡入；开启语音时，每句在语音开始播放时显示，等待合成时提示正在准备语音，失败时回退显示文字。前面的气泡保留，长回复可滚动。顶部「显示全部」可提前显示已生成文字，‹ / › 回看整轮消息。可以随时发送下一条，完整回复仍保留在历史中；收起、新对话会停止旧播放，播放期间不会自动收起。Enter 发送，Shift+Enter 换行。「···」提供新对话、人设与模型设置。聊天使用独立上下文，不自动携带论文、截图或游戏局面。
- **流式与朗读**：使用 Chat Completions 接口时，模型可逐个生成气泡（模型设置「流式显示」可关闭）；开启朗读后，文字随对应语音一起显示。模型设置中选择 MiniMax 语音接口、填写服务地址、模型、音色 ID 与独立的语音 API 密钥并开启「语音」，即可朗读、随时打断。默认地址为国内平台 `https://api.minimaxi.com/v1/t2a_v2`；国际平台可填 `https://api.minimax.io/v1/t2a_v2` 并使用对应平台密钥。语音密钥可选用 Windows 账户加密保存，也可通过 `AMEATH_TTS_API_KEY` 环境变量提供。支持的模型与音色以账户权限为准；语音服务用量可能产生费用。
- **本地爱弥斯音色**：模型设置中选择「爱弥斯本地音色 · GPT-SoVITS」并开启语音，本机安装了专用模型时会按需启动语音服务，桌宠退出或切换音色时停止；首次加载需要等待。每个气泡按句合成并在播放时预取下一句。保留参考音色但不把参考台词当作语义提示，并以本地语音识别及静音检查筛除明显异常，允许短暂自然的“嗯”等语气词；多次检查失败会停止朗读并保留文字。识别可能误判，不能保证每次都准确。与 MiniMax 可切换。本地模型、离线语音检查模型及独立环境保存在 `.local/aemeath-voice/`，不随仓库分发；见 [验证记录](docs/validation/2026-10-27-voice-text-sync.md)。
- **每日天气问候**：设置城市后，每天首次启动先入场，再用爱弥斯口吻聊当天的天气、温度及与昨天的差异；同一天重复启动不会重复问候。
- **番茄钟**：工作／休息时间、循环次数可调，默认 50 / 10 分钟、2 轮。到点会飞到当前屏幕中央提醒休息；支持暂停、继续、稍后 5 分钟、跳过休息及结束。
- **人设卡与长期记忆**：编辑身份、性格、说话风格、相处方式和背景，导入或导出 JSON 人设卡；自动提取用户明确说出的长期偏好，也可手动新增、修改和删除记忆。
- **往事与日常**：聊天超出当前上下文、点「新对话」或下次启动时，由模型把旧聊天整理成简短摘要并删除原文。「往事」是真实聊过的事，「日常」是爱弥斯讲过的原创小故事，可跨会话接着讲；都与长期记忆分开，可在「记忆与人设 → 往事与日常」查看、删除、清空或关闭。演示模式不记录。
- **主动陪伴（可选）**：右键勾选「允许主动找我聊」后，隔了几小时再来找她时会先打招呼，闲着时偶尔分享自己的小事。23:00–07:00、番茄钟、阅读或游戏任务进行中不会开口，每天最多 3 次，两次至少间隔 45 分钟。右键「安静两小时」或在聊天里说“安静一会儿”“别打扰”会让她静默两小时。闲时分享只依据在本应用里的互动判断你是否在场，不读取其他应用的输入。
- **屏幕观察（可选）**：在「模型设置」切换到连接模型模式并开启「屏幕观察」，填写支持图片输入的 Chat Completions 兼容服务地址、视觉模型和独立密钥（本地服务可留空）；普通 DeepSeek 聊天配置不自动具备视觉能力。默认每 15 分钟尝试一次，可设为 5–180 分钟；夜间、安静两小时、应用内任务、聊天输入或共享的每日 3 次上限和 45 分钟冷却会推迟观察（上限计数仅在本次运行期间保留）。观察可唤醒睡着的桌宠，无法判断用户是否在电脑前。截图包含鼠标所在显示器的完整画面，包括可能出现的私人聊天或账号，直接发送给视觉服务，服务方可能保留数据并收费；本地不保存截图。可在桌宠右键「关闭屏幕观察」立即停止并丢弃未完成的回复。视觉服务密钥可用 Windows 加密保存，或设置 `AMEATH_VISION_API_KEY`。已发送的截图不能撤回。原始画面不会自动带入后续普通聊天，需要详细解释时可手动框选或提供内容。
- **桌宠动画**：基于已有 Snowcap，使用生成的补充帧实现八方向移动、转身、坐下、睡眠、唤醒和飞行。移动有加速、减速，拖拽与任务状态联动；待机没有常驻气泡。支持手动体验动作、可选自动散步和系统托盘。
- **内置论文阅读**：打开本地 PDF、切换页码、随窗口宽度缩放，拖动矩形框选择段落、公式或图表。
- **结合上下文解释**：点击「解释选区」发送选区文字与图片，以及当前页和相关页。可以继续追问；支持的引用可以点击返回原文。
- **外部阅读器接入**：先选中文字并复制，再按 `Ctrl+Alt+E` 预览，点击解释。按 `Ctrl+Alt+S` 在鼠标所在显示器框选屏幕，松开预览，点击解释才发送。外部内容不会自动关联到正在打开的 PDF。
- **轻量陪读提示**：手动开启后，仅在内置阅读区处于前台、停留至少 35 秒、没有输入问题或生成回答时提示。每页最多一次，默认至少间隔两分钟；提示不调用模型。「稍后再说」增加冷却时间。
- **概念卡片**：手动保存解释、选文与出处，保存在本机 SQLite 中；可查看、跳回原文和删除。卡片目前用于人工回顾，尚未自动参与未来问答。
- **本地演示**：无需密钥，使用明确标注的固定教学卡片体验 attention、query、softmax 等概念。未知内容只展示准备情况和原文摘录；本地演示不具备通用推理或视觉识别能力。
- **杀戮尖塔 2 技能**：读取结构化局面，提供建议、执行一步或连续自主游玩；支持战斗、地图、事件、奖励、休息点、商店与常见选牌。桌宠显示简短评论，`Ctrl+Alt+P` 随时暂停。需要桥接模组，详见 [游戏接入说明](docs/sts2.md)。

## Snowcap 动画与移动

入场结束后会挥手，随后循环待机；点击桌宠会挥手并打开输入气泡。按住左键拖动时，会按移动方向播放左右跑步；停住鼠标会恢复当前任务动作，松手后跳一下，再回到当前任务状态。松手位置会限制在所在显示器的可用区域内；拖拽不会触发点击。

待机时不显示气泡。回复和提示的气泡只短暂显示约 3.5–8 秒，然后淡出；隐藏气泡不会改变桌宠的位置或尺寸。散步会同时改变横、纵坐标，可向上、下、斜向和任意角度移动，八组方向动作按实际路径选择。转向保留步态相位，使用站姿转身帧连接；路径有平滑加速和减速，连续表情会尽量播完当前动作再衔接。

右键 →「动作」可以预览挥手、跳跃、等待、工作、回顾和失败动作，也可以选择「散步一下」。右键勾选「允许自己散步」后，空闲时每隔约 8–14 秒移动一小段，开关会保存在本机设置中，默认关闭。思考、等待操作、检查结果或暂停陪读时，不会自动散步。新任务开始会停止散步；手动拖动始终可以接管位置。

右键 →「动作」还提供「坐下休息」「睡一会儿」「起床 / 站起来」和「飞一圈」。飞行包含起飞、悬浮、二维飞行和落地过程；用户可以直接拖动接管位置。开启自动散步时，默认有约 25% 的出行会选择飞行，可通过「散步时偶尔飞行」关闭。

默认开启「自动休息与睡眠」：累计移动约 8 秒后，或白天没有互动约 2 分钟后，会坐下休息 15 秒；连续 5 分钟没有互动会睡觉。本地时间 23:00–06:00 时，闲置约 45 秒便会入睡。这里的互动指点击、拖拽、聊天输入和主动任务，不监控其他应用的键盘。聊天、阅读解释或游戏任务仍在运行时，不自动休息或睡眠。点击、拖动或在聊天框输入会唤醒；自动行为可从右键关闭，手动坐下或睡觉会保持到被唤醒。

论文解释和游戏决策共用动作状态：思考 → 工作，等待用户操作 → 等待，检查结果 → 回顾，成功 → 挥手，失败 → 失败反应。一次性动作结束后自动恢复当前任务动作。播放与移动依据实际经过的时间推进，隐藏桌宠时停止动画计时。

聊天请求等待时播放思考动作。模型以 JSON 返回给用户的回复和情绪标识，本地把打招呼 / 开心映射为挥手，兴奋 / 庆祝映射为跳跃，好奇 / 安慰映射为等待，认真思考映射为回顾，难过映射为失败反应，平常回复回到待机。道晚安可进入睡眠，休息语气可坐下，用户请求展示飞行时可飞一小圈。未知标识只回到待机，模型不能指定任意命令或控制其他应用；正在拖动时保留拖动优先级。

首次运行从本机 `%CODEX_HOME%\pets\snowcap`（默认 `%USERPROFILE%\.codex\pets\snowcap`）读取 `pet.json` 和精灵图，校验后原样复制到 Ameath 数据目录的 `pets/snowcap/`，后续使用本地副本。资源缺失或格式不符时回退到简易外观，悬停桌宠可查看提示。原始 Snowcap 文件不会被修改；该副本供这台电脑上的私人原型使用，没有随项目对外分发。

补充动画存放在 `assets/snowcap-motion-v2/` 的 `movement.png`、`actions.png`、`rest.png` 和 `flight.png`，由内置 image_gen 基于原始参考生成，原始 Snowcap 文件保留不变。`generation.json` 与 `lifecycle-generation.json` 记录生成提示词、帧序校正和行为阈值。播放器会识别透明间隙，沿用原来的比例、垂直锚点、动作顺序和节奏；待机直接播放原始 8 帧（每帧 150 毫秒）。仅逐帧对齐头部横向中心，减少左右抖动。整帧原画直接显示，不拆分部位、不做额外呼吸拉伸或帧间混合；补充图损坏时保留基础动作。

入场／退场素材位于 `assets/snowcap-lifecycle-v1/entrance.png`，由内置 image_gen 参考现有像素形象生成。声痕 → 像素聚拢 → 现身，反向播放用于退场，每次约 1.8 秒；末端与现有待机帧混合，避免硬切。生成提示与参考范围记录在同目录 `generation.json`，是依据用户描述创作的动画，不是提取的官方游戏帧。正常退出会等待动画结束，系统强制结束进程不保证能播放动画。

## 天气与问候

右键桌宠 →「天气与问候」，查找城市并选择对应省份，勾选每日首次启动问候。当前个人配置使用河南郑州；项目默认不预设位置。城市查询和天气数据来自 [Open-Meteo](https://open-meteo.com/)，不需要天气 API 密钥。仅请求所选城市坐标，不读取设备位置。设置界面可以关闭每日问候，也可随时点击「听听今天的天气」手动刷新。

天气接口返回当天的天气代码、最低／最高温和今天、昨天的日均温；日均温变化不足 1℃ 时说“和昨天差不多”，否则报告约几度的变化。昨天的数据是天气模型估计。日期缺失、数据缺失或网络失败时不编造天气，只给出简短问候；不会把失败记为当天成功播报。悬停天气回复可看来源、日期与获取时间。

模型只润色开场与收尾，天气事实由应用按核验数据插入。沿用模型设置与人设，无需提供额外密钥；模型失败时使用本地角色措辞。每日自动请求在入场结束后启动，遇到用户正在聊天或番茄钟休息时等待空闲再显示；问候约 30–60 秒后收起，点击桌宠仍可回看。成功显示的日期保存在 `.local/daily-greeting.json`，同日重启不再自动查询。手动刷新不受该限制。聊天可以引用已有天气问候，目前没有通用联网搜索工具。

## 番茄钟

右键桌宠 →「番茄钟」，调整工作 1–240 分钟、休息 1–120 分钟和 1–20 个循环后开始。一轮包含工作与休息，最后一轮也有休息。设置会保存，关闭设置窗口后继续计时；退出 Ameath 会结束本次计时，下次启动不自动续跑。

工作结束后，爱弥斯飞到所在显示器可用区域的中央，悬浮休息气泡挡住中央工作区域。可选择“稍后 5 分钟”“跳过本次休息”“结束番茄钟”，在气泡内按 Esc 也会稍后提醒；不会锁定键盘或整个桌面。休息结束后飞回先前的位置，自动进入下一轮。暂停会冻结剩余时间；电脑长时间挂起后，恢复时仍会进入一段完整休息，不会把几轮休息直接跳过。

在其他数据目录或新安装中，可从「记忆与人设 → 导入人设卡」选择上述主卡，然后点击「保存人设」。模型连接与工具能力仍由应用设置决定；本地演示使用固定回复，不代表模型实际的人设表现。

## 连接模型

在输入气泡的「···」或 App 左下角点击「模型设置」，选择 **使用 DeepSeek 预设**，填写 DeepSeek API 密钥并保存。默认地址为 `https://api.deepseek.com`，接口为 Chat Completions，模型为 `deepseek-flash`。这套设置同时驱动聊天、阅读、截图解释和游戏决策。旧版未配置的演示设置会迁移到 DeepSeek 预设；已有真实服务配置保留，可以通过预设按钮切换。

普通解释默认关闭深度思考；游戏默认开启，并可选择 low / high / max 强度。DeepSeek 请求使用其原生 `thinking`、`reasoning_effort` 和 `max_tokens` 字段。游戏每次只请求一个 JSON 最终决策，模型从本轮给出的动作 ID 中选择；不把模型内部思考当作桌宠评论，也不存入日志。

DeepSeek 聊天首轮不启用接口的强制 JSON 模式，以避开本机反复出现的 HTTP 200 / stop / 空回答组合；保留已选的深度思考设置。提示词仍要求 JSON 对象，reply 为按说话顺序排列的段落数组，并将历史助手回复统一编码为同样的格式。解析器保留旧字符串与纯文本回复兼容，正式代码、表格不会按字数硬切。收到完整结果后在本地播放气泡和淡入，不展示内部思考，也不增加分段 API 请求。

聊天遇到空回答、输出额度用尽或不完整的回复格式时，会保留本轮问题与人设，临时关闭深度思考、移除其他兼容服务的 JSON 模式限制，最多自动重试一次。重试会增加一次 API 请求，不修改保存的深度思考设置。余额不足、密钥、权限、网络与内容过滤错误会显示对应原因，不自动重试。论文与游戏请求不使用这项聊天兼容策略。

聊天按交流意图而非工作关键词决定是否提供方案：分享论文、考试或申请近况时保留日常相处方式，明确求助时正常分析和完成任务。主动关心与任务管理分开：爱弥斯可以主动心疼、俏皮护短、替用户抱不平或分享小主意，不默认以‘我在这里陪着’被动收尾；用户明确想安静或不想开玩笑时顺着调整。语气词、转折和短接话按语境使用，不固定每轮追问，也不把‘打飞’变成固定口头禅或飞行动作；正式语体只用于用户要求的正式成品。闲聊鼓励她分享自己的具体小事、直接表达偏好，减少句末反问、动机揣测和正反总结。当前主卡的 background 写入了常做的音乐创作、游戏、小整理，以及偶尔的动手试验、发呆与灵感，每类都有可聊的进展和小意外，随主卡实际发送给模型；这是可选择的角色生活素材，不是自动日程或后台活动。角色日常可在扮演内原创并沿当前对话延续，不写入用户长期记忆，也不冒充官方剧情或现实工具执行。聊天分段规则位于 `ameath/chat.py`，气泡节奏参数位于 `ReplyBubble` 的 `FADE_MS`、`MIN_PAUSE_MS`、`MAX_PAUSE_MS`。

最近 20 条模型返回状态保存在 `.local/model-diagnostics.jsonl`，仅包含时间、模型、接口、HTTP 状态、停止原因与错误类别，方便区分空回答和输出截断；不记录聊天正文、长期记忆、内部思考或密钥。[DeepSeek 官方 JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/) 提到该模式偶尔可能返回空内容。

默认 Flash 模型及图像支持以 [DeepSeek 当前官方文档](https://api-docs.deepseek.com/) 和 [图像输入文档](https://api-docs.deepseek.com/guides/vision/) 为依据。接入其他兼容服务时，可自行填写地址与模型；游戏技能要求 Chat Completions 与 JSON 输出兼容。

密钥可仅在本次会话使用，也可勾选通过 Windows DPAPI 在当前账户下加密保存。另支持 `AMEATH_API_KEY`，以及连接官方 DeepSeek 地址时的 `DEEPSEEK_API_KEY` 环境变量。不要把密钥写进代码或提交到仓库。Ameath 不把密钥交给游戏模组。

产品与项目文件夹现统一为 AmeathAgent，角色中文名为爱弥斯，设置界面采用樱粉与奶白配色；原有 `.local/` 设置、加密密钥、卡片和游戏记录沿用，旧的 `VIOLET_API_KEY` 与 `VIOLET_DATA_DIR` 环境变量继续兼容。代码包现在为 `ameath`，启动入口为 `启动AmeathAgent.cmd`。

原型没有预置 API 密钥，也没有代用户开通模型服务。界面上的「模型模式」代表配置状态，实际连接结果以发起解释后的返回为准。

## 记忆与人设

在输入气泡的「···」点击「记忆与人设」，或从桌宠右键菜单进入。人设卡提供角色名称、身份、性格、说话风格、相处方式和背景；保存后用于后续聊天。可导入、导出版本为 1 的 JSON 卡片。默认人设是温和、好奇、坦诚的 Ameath。

长期记忆与当前聊天上下文分开保存：当前对话仅保留在运行中的内存里，给模型最多带最近 6 轮；长期记忆保存在本机 SQLite，可跨重启使用。启用自动记忆时，模型在同一次回复里最多建议 3 条用户明确说出的长期事实或偏好，应用校验后保存，不增加一次独立的记忆提取请求。自动提取依赖模型判断，可在管理界面核对、更正。

长期记忆最多 200 条，每条内容最多 360 字；每轮按关键词和最近更新时间选择最多 12 条作为背景资料。它们用于日常聊天，暂不接入阅读解释或游戏决策。明显的密码、密钥和证件类内容会被过滤。手动更正、删除记忆后，下次请求使用更新后的数据；当前对话里已经提到的内容仍属于短期上下文，点击「新对话」可以清空。

「自动记住我明确说过的长期事实和偏好」控制新记忆的自动保存；「聊天时使用人设与相关记忆」控制是否把已保存的人设和相关记忆随聊天发送给配置的模型 API。关闭后仍可在本机编辑，并清空后续发送给模型的短期上下文，避免历史回复再次带出已保存的内容；屏幕上已有的聊天记录仍可查看。删除本机记忆无法撤回先前已经发出的请求。

本地演示只提供固定回复与动作，不进行开放式推理或自动偏好识别。可输入 `记住：我喜欢红茶` 体验备注保存，输入 `你记住了什么` 查看当前保存的背景；开启模型模式后才使用真实模型理解新信息。

## 数据范围

陪读开关只控制内置阅读区的本地提示，暂停后仍可主动发起解释。应用不监控键盘、不自动读取剪贴板。剪贴板仅在用户触发入口时读取；截图由手动框选或用户明确启用的定时屏幕观察采集。

整屏画面仅短暂用于选区操作，选定后只保留裁剪区域。截图不写入磁盘；清除上下文或退出会释放应用持有的选区。已经发送的请求可能仍在服务端完成，点击停止会忽略其返回；无法撤回已发送的内容。

聊天请求包含当前消息、最多最近 6 轮对话、本地时间，以及启用时的人设卡和最多 12 条相关长期记忆；不自动读取文件或其他应用。应用另有天气接口，按用户选择的城市查询；天气问候会将已核验的天气事实和启用的人设发送给配置的模型，生成开场与收尾。当前没有通用联网搜索，模型不会因接入 API 就获得任意实时查询能力。阅读请求包含当前问题、选文、最多四个相关页的有限文本、本轮最近的少量对话，以及本次选择的图片。游戏请求包含当前紧凑局面、合法动作列表、最近五步与短期目标；只有用户启动建议或接管时才调用模型。服务方的日志和保留行为以其政策为准。回答中的外链不会自动打开，也无法加载本地或远程图片资源。

设置、加密凭据、示例 PDF、人设卡 `persona.json`、长期记忆 `companion.sqlite3`、概念卡片及游戏决策日志存放在项目的 `.local/` 中，该目录已被 Git 忽略。游戏日志只记录局面标识、动作、最终理由、评论和已报告用量，不保存密钥、原始游戏截图或内部思考。聊天全文和普通论文问答历史不写入磁盘，提取的长期记忆单独保存；默认不保存原始论文副本。可通过 `AMEATH_DATA_DIR` 改变数据目录。

## 原型边界

- 第一版优先保证一个可控的阅读入口。尚未接入外部阅读器的自动选区、页码识别、UI Automation 或持续屏幕理解。
- 相关页检索使用关键词和位置，不是向量检索。复杂双栏、跨页论证和公式仍需要核对原文。扫描件没有本地 OCR，可借助视觉模型解释当前页或选区。
- 暂支持 100 MB 以内的未加密 PDF。全文提取在打开时完成，较长文档可能需要等待。
- 主动提示目前是确定性规则，不推断注视位置，也不把停留时间视为没理解的证据。
- 游戏技能目前只接管单人局，从已开始的对局接手；特殊未映射界面、人工暂停、局面变化、接口异常或额度耗尽会停止。没有验证 DeepSeek 的真实对局胜率，也不保证所有局面都能无人值守通过。
- 尚未加入语音、PPT 建议、任意游戏的视觉操作、通用电脑控制或安装包。
- 通用模型解释的质量、费用、延迟取决于实际接入的服务。自动化测试使用本地接口模拟服务；部分聊天人设另做了真实 DeepSeek 小样本验证，不能替代长时间使用或游戏实机验收。

检查覆盖阅读选区、原文检索、引用、离线与模型请求分离、本地 HTTP 序列化、重定向阻断、加密凭据、提示节奏、卡片、过期请求隔离，以及逐帧时序、动作优先级、移动、拖拽和屏幕边界。界面检查在独立的离屏画布上进行，只渲染 Ameath 自己，不捕获用户桌面。

`tools/preview_game.py` 渲染游戏面板的演示预览；`tools/probe_sts2.py` 只读检查已启动的游戏桥接，不调用模型或执行动作。

## 代码入口

`ameath/app.py` 负责桌面流程；`chat.py` 与 `chat_ui.py` 管理聊天，`memory.py` 与 `companion_ui.py` 管理人设和长期记忆；`sprites.py` 校验和播放精灵图，`pet.py` 管理桌宠绘制、移动与拖拽；`reader.py` 与 `papers.py` 处理阅读与原文；`capture.py` 实现手动选区；`llm.py` 是所有技能共用的模型调用核心，`agent.py` 是阅读技能；`game.py` 与 `game_ui.py` 管理游戏桥接、决策、暂停与用量；`policy.py` 管理提示节奏；`storage.py` 保存卡片；`config.py` 管理配置与加密凭据。

后续工作的状态、优先级和验收统一记录在 [当前任务台账](docs/BACKLOG.md)，阅读器、游戏和角色体验分别按实际证据推进。
